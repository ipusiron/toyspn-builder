**Day094 - 生成AIで作るセキュリティツール100**

ToySPN Builderは、S-Boxによる値の置換、P層によるビットの並べ替え、ラウンド鍵のXORからなるSPN（Substitution-Permutation Network）を設計して動かす教育用Webツールです。
暗号化と復号の途中経過、1ビットの入力差に対する出力変化を観察できます。

ヒル暗号の線形変換と、非線形なS-Boxを使う構成を比べる教材です。
鍵とブロックは16ビットしかありません。実際の秘密情報の保護には使えません。

## 🚀 クイックスタート

### 基本的な使い方

1. 「暗号化/復号」タブの「標準サンプル」を押す。
   SとPはデフォルト、鍵は `C0DE`、ラウンド数は8、平文は `1234` になる。
2. 「暗号化」を押す。
   暗号文 `FBC6` と、8ラウンドの途中経過が表示される。
3. 同じ設定のまま「復号」を押す。
   平文が `1234` に戻ることを確認する。
4. 「解析」タブで試行回数200のまま「実行」を押す。
   ヒストグラム、表、平均値と実行条件を確認する。
5. 「学習」タブで、関係する説明を開く。

平文、暗号文、鍵は16進数1〜4桁です。
大文字と小文字を使え、先頭の0は省略できます。
空欄、記号、範囲外の整数などはエラーになります。

### 実験的な使い方

- 設計タブでS、P、鍵、ラウンド数を1項目ずつ変更する。
- 「恒等S-Box」「恒等P層」「最小1」で、操作を単純化して観察する。
- 解析の試行回数は10〜2000の整数で指定する。

設定を変えると、その設定から作られた結果は消えます。
平文と暗号文の入力欄は保持されますが、新しい設定の計算結果ではありません。
「標準サンプル」はS、P、鍵、ラウンド数、平文を初期値に戻し、暗号文と結果を消します。試行回数は保持します。
ボタンの下にも変更する範囲を表示し、読み込み後に設定した値を通知します。

「暗号化/復号」と「解析」には、現在のラウンド数、鍵、S/Pの種類を表示します。
S/Pの種類は標準、恒等、カスタム、要修正のいずれかです。入力が未確定の間は「入力中」と表示します。
この表示は現在の入力に追従し、解析結果の「実行時の条件と結果」とは区別しています。
実行前は操作案内、結果が失効した後は再実行の案内を表示します。解析中とエラー時にも状態を通知します。

ヘッダー右上のボタンで日本語と英語を切り替えられます。
狭い画面ではタイトルより上の右側に配置し、機能を選ぶタブとは分けています。
初期言語は `?lang=ja|en`、保存済みの選択、ブラウザーの言語の順に決まります。
言語以外の入力値や結果は保存せず、言語切替で解析をやり直すこともありません。
保存が禁止されている環境でも切替は利用できます。

## 🌉 ヒル暗号からToySPN Builderへの橋わたし

### 1️⃣ ヒル暗号の仕組み

ヒル暗号は、行列を使って文字を変換する暗号です。
「A=0, B=1, …, Z=25」として、複数の文字をベクトルにします。

```text
暗号文 = 鍵行列 × 平文（mod 26）
```

復号には、mod 26で逆行列を持つ鍵行列が必要です。
十分な独立した平文と暗号文の組がわかれば、連立方程式から鍵行列を求められます。
仕組みを知っていることだけでなく、攻撃に使える組の数と独立性が条件になります。

[Hill CipherLab](https://ipusiron.github.io/hill-cipherlab/)では、行列演算や既知平文からの鍵回復を学べます。
文字を扱うヒル暗号と、ビットを扱う本ツールでは、計算する集合が異なります。

### 2️⃣ 現代の暗号で使われる非線形変換

SPN型のブロック暗号では、性質の異なる変換を組み合わせます。

1. S-Box（エスボックス）
   入力値を表で置き換える。非線形な表を選ぶと、線形関係だけでは表せない変換になる。
   任意の置換表が非線形とは限らない。
2. P層（Permutation Layer）
   ビット位置を並べ替える。次のラウンドで、どのS-Boxに変化が伝わるかを変える。
   P層だけでは反転ビット数は増えない。
3. AddRoundKey（鍵加算）
   ラウンド鍵をXORする。同じ鍵をもう一度XORすると元に戻る。
   この可逆性を復号に利用する。

この組み合わせだけで安全性は決まりません。
S-Boxの性質、鍵導出、ブロック長、鍵長なども検討対象になります。

### 3️⃣ ToySPN Builderの構成

本ツールは、3つの操作を小さなブロックで観察できます。

1. S-Box：4ビットの値（0〜15）を置き換える。
   デフォルトの表は「0→C、1→5、2→6…」。
   恒等S-Boxでは値を変更しないため、非線形変換にならない。
2. P層：16個のビット位置を並べ替える。
   GF(2)上の線形変換であり、各ビットの値は変えない。
   ヒル暗号も線形変換を使うが、同じ演算ではない。
3. AddRoundKey：各ラウンドの最後に鍵をXORする。
   S-Box、P層、鍵XORを指定回数繰り返す。
   AESそのものの実装や簡略版ではない。

### 4️⃣ ヒル暗号とのちがいとつながり

| 比べる項目 | ヒル暗号 | ToySPN Builder |
| --- | --- | --- |
| 変換の種類 | mod 26の行列計算 | S-Box＋GF(2)上のP層＋鍵XOR |
| 拡散 | 行列の掛け算 | S-Boxとラウンド間のビットの並べ替え |
| 鍵の使い方 | 鍵行列 | 毎ラウンドの鍵をXOR |
| 可逆性 | 鍵行列が可逆 | SとPが全単射 |
| 実用上の位置付け | 学習用であり秘密情報の保護には不適 | 16ビットの学習用であり秘密情報の保護には不適 |

どちらも、暗号化の各操作を逆にたどれることが復号の条件です。
一方、復号できることと、攻撃に強いことは別の性質です。

### 5️⃣ 非線形性と安全性の区別

線形な変換は、十分な独立した入出力がわかると、行列として求められます。
非線形なS-Boxは、その方法をそのまま適用できない変換を導入します。
「数式で書けること」が弱点なのではなく、利用できる線形関係が問題です。

S-Boxが全単射であっても、非線形性や差分解析への耐性は保証されません。
本ツールはこれらの耐性を測定しません。
表を変えたときの出力差と、暗号学的な安全性を区別して観察してください。

### 6️⃣ アバランシェ効果（なだれ効果）の観測

入力の1ビットだけを変え、暗号文どうしのハミング距離を数えます。
「解析」タブでは、ランダムな平文と反転位置で繰り返した結果を表示します。

各出力ビットが確率1/2で反転するモデルでは、平均は8ビットです。
ただし、平均が8に近いだけでは、各ビットの反転確率や独立性はわかりません。
SAC（厳密ななだれ基準）や暗号の安全性の合格判定には使えません。

- SやPを変えると、平均や分布が変わる場合がある。
- ラウンドを増やしても、反転ビット数が増えるとは限らない。
- 同じ設定でも、抽出する平文と反転位置により測定結果は変わる。

### 7️⃣ 学習で区別する性質

- 全単射：逆の変換を作れること。
- 非線形性：線形な関係だけでは表せないこと。
- なだれ効果の観測：選んだ条件で出力差がどの程度広がるか。
- 安全性：特定の攻撃に対する評価を含む、観測値だけでは判断できない性質。

本ツールでは、この4つを同じ意味で扱わず、設定と結果の関係を学びます。

## 📚 本ツールの活用シナリオ

### 🧪 シナリオ1：恒等S-Boxで差の伝わり方を調べる

目的：値の置換と、ビット位置の並べ替えを区別すること。

手順：

1. デフォルト設定でなだれ効果テストを実行し、結果をメモする。
2. 設計タブの「恒等S-Box（値を変えない）」を押す。
3. 解析タブで再実行する。
4. 分布表と「結果の読み方」を確認する。

確認できる結果：

- 有効なP層と鍵なら、1〜16ラウンドのどの場合も平均反転ビット数は正確に1。
- P層は差の位置を変えるだけで、固定鍵のXORも差の数を変えない。
- S-Boxの図は入力と同じ出力へ結ぶ垂直線になる。

これは、恒等S-Boxに対する性質です。
一般の線形S-Boxがすべて平均1になるという意味ではありません。

### 🔬 シナリオ2：ラウンド数と出力差の関係を調べる

目的：ラウンド数を増やす効果を、測定によって確認すること。

手順：

1. 標準サンプルで初期設定に戻し、ラウンド数を1にする。
2. なだれ効果テストを実行して、条件と結果をメモする。
3. ラウンド数を4、8、16に変え、それぞれ実行する。
4. 平均だけでなく分布も比較する。

各ラウンド数の測定値には決められた合格範囲はありません。
異なる試行では標本も変わるため、差をそのままラウンド数だけの効果とは解釈できません。

反例を調べるには、Sを `[0,E,D,3,B,5,6,8,7,9,A,4,C,2,1,F]`、Pをデフォルトにします。
この線形S-Boxでは、すべての入力について各ビット差を平均すると、1〜4ラウンドの平均は `3, 9, 3, 1` です。
UIの有限回のランダム試行とは区別してください。
回数が増えるほど平均が8へ近づくとは限らないことを、計算で確認できます。

### 🎨 シナリオ3：独自の表で可逆性と観測値を調べる

目的：全単射の成立と、測定結果の特徴を別々に確認すること。

手順：

1. S-Boxの「ランダム生成」を押して、対応関係の図を見る。
2. P層もランダム生成する。
3. マスター鍵もランダム生成する。
4. 「設定を検証」で表の全単射性を確認する。
5. 平文 `1234` を暗号化し、同じ設定のまま復号する。
6. なだれ効果テストを実行し、条件と分布をメモする。
7. 次は1項目だけ変えて比較する。

生成されたSとPは全単射なので、有効な鍵とラウンド数のもとで復号できます。
ただし、ランダム生成は非線形性や暗号の安全性を保証しません。
異なるSとPの組み合わせが同じ平均値を示しても、同じ暗号学的性質とは限りません。

## ⚙️ ミニSPNのアルゴリズム

- 状態は 16-bit。毎ラウンド：
  1. SubNib：各4-bitニブルに S-Box を適用
  2. PermuteBits：ビット位置の全単射置換（線形）
  3. AddRoundKey：ラウンド鍵と XOR
- 復号は逆順で XOR → InvP → InvS
- 鍵スケジュールは 16-bit master key を 左回転＋ラウンド定数XOR で生成

> S は置換（全単射）、P は置換行列（可逆）、AddRoundKey は XOR。
> いずれも 可逆 であることが復号の必要条件です。

## 🔧 デフォルトパラメーター

- S:
  `S = [C,5,6,B,9,0,A,D,3,E,F,8,4,7,1,2]`（16進）
  ※ UIで編集可能。逆写像は復号時に生成。
- P:
  `P = [0,4,8,12, 1,5,9,13, 2,6,10,14, 3,7,11,15]`（bit 0..15 → P[i]へ）
- Rounds: 8
- Master Key: 16bit（例: `C0DE`）

## ⚠️ 制限事項

- 鍵とブロックは16ビット。鍵は65,536通りしかなく、秘密情報の保護には使用不可。
- 単一ブロックの教材。ECBなどの暗号利用モード、パディング、認証、ファイル暗号化は未実装。
- なだれ効果は選んだ条件での観測。SAC、差分耐性、線形耐性、暗号強度の判定は未実装。
- 全単射は可逆性の条件。非線形性や安全性を保証する条件ではない。
- ラウンド増加や乱数の使用だけで、実用的な暗号にはならない。
- Web Cryptoを利用できない場合、ランダム生成と解析は失敗を通知。弱い乱数への代替は行わない。
- 設定の保存、共有、エクスポートは未実装。保存するのは表示言語だけ。

実際の情報保護には、用途に適した標準暗号と検証された実装を利用してください。
ブラウザー上の対策と、教材としての暗号の安全性は別です。
[セキュリティ対策と限界](SECURITY.md)も参照してください。

## 💻 動作環境とテスト

JavaScript、SVG、Canvas、Web Cryptoに対応したブラウザーを使用してください。
外部ライブラリー、CDN、ビルド処理は不要です。
ダウンロードしたフォルダーの `index.html` を開くか、ローカルHTTPサーバーで利用できます。

```sh
python -m http.server 8000 --bind 127.0.0.1
```

テストはNode.js 22以降の標準機能で実行します。npm installは不要です。

```sh
npm test
```

GitHub Actionsでもpushとpull_request時に実行します。
単体テストに加え、画面変更時はHTTPとfile://、日本語と英語、狭い画面、キーボード操作をブラウザーで確認してください。
